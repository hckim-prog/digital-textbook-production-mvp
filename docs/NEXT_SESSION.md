# 다음 PC에서 작업 이어가기

## 현재 상태

2026-09-22 기준 Windows 데스크톱 MVP입니다. DOCX 원고를 구조화한 뒤 AI 교정 제안을 사람이 승인하고 HTML/PDF/EPUB을 제작합니다.

- 교정/교열 → 기술 검토 → 최종 검토 순서로 앞 단계 승인 내용을 이어받습니다.
- 기존 승인·보류 기록을 보존하고, 후속 단계의 기준 문장이 바뀌면 다시 검토하도록 표시합니다.
- 전체 원고 또는 일부 문단 시험, 검토 중단과 이어서 검토를 지원합니다.
- 밝은 화면, 변경 부분 강조, 원문·수정 제안 나란히 보기를 적용했습니다.
- DOCX 코드의 줄바꿈·공백·탭·빈 줄을 보존하고 실제 출력에서 대조합니다.
- 개발 PC에서 자동 테스트 32개와 고정 시험 응답을 사용하는 EXE 검증을 통과했습니다. 실제 원고가 없는 환경에서는 일부 원고 검사가 생략됩니다.

## 다음에 논의할 기능

**장 → 절 → 소단원 자동 구조 분석**은 조사와 제안까지만 진행했습니다. 아직 구현하지 않았으며, 사용자가 구현을 지시하면 착수합니다.

추천 방향:

1. 기존 DOCX 읽기 기능을 유지하고 제목 스타일·개요 수준·번호·서식을 함께 분석합니다.
2. 기존 제목 복원과 제목 없는 본문의 새 구성 제안을 구분합니다.
3. AI는 본문 재작성 대신 제목, 상위 항목, 시작·끝 블록과 분류 근거를 제안합니다.
4. 목차 트리와 실제 본문을 함께 보여주고 사용자가 수준·제목·경계를 수정해 승인합니다.
5. 승인한 구조를 중간 원고에 저장하고 HTML 제목·목차, PDF 제목·책갈피, EPUB 탐색 목차에 연결합니다.
6. 본문 누락·중복·순서 변경과 코드·표·그림·캡션 훼손 여부를 검사합니다.

현재 `core/master.py`에는 장·절·소단원 관계가 없고, `core/export/outputs.py`는 제목을 같은 수준으로 출력합니다. 글자 크기만 바꾸는 수정으로 끝내지 않습니다. 제목 수준이 실제 의미와 맞지 않는 DOCX도 고려해야 합니다.

본문 번호 목록·그림 번호를 소단원으로 오인하지 않고, 학습목표·요약·연습문제·팁을 구분합니다. 부분 발췌본의 전체 목차를 실제 본문으로 오인하지 않습니다. 기존 제목을 우선 보존하며 AI가 만든 제목은 승인 전까지 제안으로 표시합니다. PDF 직접 입력은 별도 후속 범위입니다.

## 새 PC 준비

저장소 루트 README의 설치 명령을 실행하세요. Python 3.12와 Git이 필요합니다. API 키는 각 PC의 `.env`에 직접 설정합니다. 원고 없이도 합성 문서를 이용한 자동 테스트와 `--verify-review-flow` 실행이 가능합니다.

공개 저장소에는 API 키, 실제 교재 원고, 참고 PDF, 회의 문서, 검토 기록, 생성 결과물, 실행파일, 로컬 백업을 넣지 않았습니다. 기존 작업을 그대로 이어가려면 원고와 `working` 폴더를 개인 저장장치 등으로 별도 이동해야 합니다. 원고를 새 PC에서 다시 선택하고, 저장 위치도 새 경로로 지정하세요.

`--verify-review-flow`는 유료 API를 호출하지 않습니다. 실제 API 테스트·교정·모델 비교는 비용이 발생할 수 있으므로 실행 범위를 먼저 확인합니다.
